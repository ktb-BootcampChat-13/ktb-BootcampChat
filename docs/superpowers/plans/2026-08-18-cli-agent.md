# CLI Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Python CLI agent backed by Ollama `qwen2.5` with short-term conversation memory, model-selected date/time tool calling, bounded loops, graceful errors, and JSON history saving.

**Architecture:** `main.py` owns argument parsing and standard I/O, `agent.py` owns conversation state and the bounded model/tool loop, `tools.py` owns tool definitions and dispatch, and `history.py` owns persistence. Ollama is injected behind a small client interface so unit tests can use deterministic fakes.

**Tech Stack:** Python 3.10+, `ollama` Python package, standard-library `argparse`, `datetime`, and `json`, plus `pytest` for tests.

**Spec:** `docs/superpowers/specs/2026-08-18-cli-agent-design.md`

## Global Constraints

- All implementation files live under `cli-agent/`.
- Default model is exactly `qwen2.5` and can be replaced with `--model`.
- Default per-turn tool-loop limit is exactly `3` and must be positive.
- Conversation history is kept only for the current process and saved to `history.json` on exit; it is not restored automatically.
- The only exposed tool is `get_datetime`.
- Expected runtime failures must be shown to the user without an unhandled traceback.
